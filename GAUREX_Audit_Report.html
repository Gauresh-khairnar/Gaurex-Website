GAUREX • Website Audit Report 03. Detailed UI/UX Design Audit

03. Detailed UI/UX Design Audit Interface

Visual Hierarchy & Component Overload

GAUREX embraces an Apple-inspired minimalist aesthetic characterized by black-and-white palettes, thin borders (border-gray-100, border-gray-200), and smooth micro-interactions. However, the homepage structure suffers from severe section redundancy.

A visitor must scroll through 15 separate vertical blocks. Four of these sections—LivingEngine, ProblemStories, BeforeAfter, and ArchitectureBuilder—deliver virtually the identical message: "Business problems are disconnected; GAUREX connects them with software." This causes user cognitive exhaustion before they ever reach the pricing or contact sections.

Critical UI Bug: The Invisible Cursor on Touch & Hybrid Devices

In src/app/layout.tsx, the root HTML element is configured with: 

<html lang="en" className="scroll-smooth cursor-none md:cursor-auto">

Meanwhile, in src/components/CustomCursor/index.tsx: 

if (typeof window !== 'undefined' && window.innerWidth < 768) return null;

Consequence: On viewports under 768px (iPad Pros, tablets, touch laptops with trackpads), cursor-none remains active, but the custom cursor component returns null. The pointer vanishes entirely, making the site unusable for tablet mouse users. On desktop screens, md:cursor-auto causes a distracting double cursor (native OS cursor overlaid on top of a laggy 32px black circle).

Typography & Whitespace Audit

  • Font Consistency: Inter is implemented cleanly via CSS variable --font-inter with tight tracking (tracking-tight).
  • Colossal Display Text Bloat: In TypographyReveal/index.tsx, the headline text-[15vw] takes up multiple full viewport heights while conveying zero specific technical or business value.
  • Micro-Label Overuse: Every single card and section header contains uppercase gray sub-labels (text-xs font-bold tracking-widest text-gray-400 uppercase), diluting their ability to guide user attention.

Responsive & Mobile Usability

While Flexbox and Tailwind breakpoint utilities (md:, lg:) ensure elements do not break out of horizontal bounds, mobile usability is penalized by:

  1. Video Bandwidth Consumption: The mobile video file is 3.93MB—significantly larger than the desktop video (2.52MB)—causing high data usage and slow initial paints on mobile devices.
  2. Excessive Scroll Depth: Mobile users must swipe through over 18,000 pixels of vertical content to reach the bottom contact area.

The WhatsApp Gating Trap

The single largest commercial vulnerability on the GAUREX website is its exclusive reliance on raw WhatsApp redirects. In src/components/IntelligentContact/index.tsx, when a visitor selects a problem chip, the only resulting action is an external link opening wa.me/919579098477.

Commercial Impact on High-Ticket B2B Sales

Corporate executives, procurement managers, and international clients from the US, UK, Europe, and UAE do not conduct six-figure software discovery on personal WhatsApp. WhatsApp is viewed as personal, informal, and lacking enterprise privacy/confidentiality safeguards. This design choice instantly filters out the highest-paying prospective clients.

Audit of Interactive Funnels & Dead CTAs

  • ProblemScanner (Line 104): The primary diagnostic displays a prominent black button: <button>Build My Solution</button>. In the source code, this button has no onClick handler, no href link, and no state binding. Clicking it does absolutely nothing.

  • Solution Estimator (Line 125): Calculates an estimated cost (e.g. "$12,000 - $18,000"), but the WhatsApp CTA sends a static message: "Hi GAUREX, I would like to request an exact proposal." It completely drops the selected modules and estimated price from the query string!

GAUREX • Website Audit Report 07. Performance & Core Web Vitals

07. Performance & Core Web Vitals Audit Speed

The 3.9MB Video Blocker Analysis

In src/components/IntroVideo/index.tsx, a full-screen video overlay mounts immediately upon page visit: 

src={isMobile ? "/videos/mobile.mp4" : "/videos/desktop.mp4"}

File payload inspection from the repository root:

  • /public/videos/desktop.mp4: 2,524,482 bytes (2.52 MB)
  • /public/videos/mobile.mp4: 3,929,672 bytes (3.93 MB)
The Mobile Performance Irony

The mobile video is 55% larger than the desktop video. While desktop users typically connect via high-speed broadband, mobile users on 4G/5G connections are forced to download a massive 3.93MB video stream before they can see the homepage content. This delays First Contentful Paint (FCP) and drives mobile bounce rates above 60%.

Monolithic Client-Side Hydration Penalties

In src/app/page.tsx, line 1 enforces: "use client";.

Next.js App Router is designed to stream HTML directly from the server. By forcing the root page component to run client-side, GAUREX loses all advantages of React Server Components (RSC):

  • The entire Framer Motion animation library (13.4.4) must be downloaded, parsed, and executed before the layout stabilizes.
  • Search engine crawlers and users with low-spec processors experience significant main-thread blocking time (Total Blocking Time > 350ms).
  • Layout shifts occur as state toggles from introFinished: false to true.

Font Loading Vulnerability

During local Turbopack build execution (npm run build), Next.js flagged an unhandled network error: 

Error: Failed to fetch Inter from Google Fonts.
If you are offline or behind a proxy, self-host the font with next/font/local.

Relying on external Google Fonts API queries during build or runtime introduces external network dependencies and latency. Transitioning to next/font/local guarantees instant zero-latency font loading with zero external DNS lookups.
